## graphify

Graphify 0.9.96 is installed (`graphify` in PATH) and the skill is installed globally; the generated graph lives in `graphify-out/`.

**Limitation (checked 2026-10-27):** graphify does not parse GDScript. `.gd` files are reported as unclassified (42 files skipped) and have no nodes. The graph covers `GDD.md`, `AGENTS.md`, `.opencode/**`, `data/*.json` and `tools/*.py` only. Do not use it for questions about `scripts/**/*.gd` or `tests/*.gd`.

Rules:
- Graph content is document headings plus Python/JSON entities. `graphify explain "<точный заголовок>"` and `path` work; `graphify query` matches labels literally (no synonyms), so a natural-language question usually returns "No matching nodes" — use exact section names or skip it. For GDScript use grep/read.
- Do not put the "graphify first" rule into subagent prompts that explore GDScript: the result will be empty or noise.
- `graphify update .` after changing docs or Python tools; it will not add `.gd` nodes. `query`/`path`/`explain` exit 0 with an answer, 3 when a name is ambiguous, 4 when no node matches.
- `graphify-out/` is generated: don't hand-edit `graph.json`. The OpenCode shell-hook plugin was removed because its "query before grep" reminder is wrong for GDScript.
- If a code graph is needed later, either add a GDScript-aware indexer or emit a symbol index and feed it as a document; don't pretend the current graph covers the game code.
